## 검수 방법 (§5 확장)

1. **STT 교차 대조** — 각 wav를 Gemini 멀티모달 모델로 받아쓰고 대본과 정규화 비교(`qa_transcribe.py`). 쿼터 분산을 위해 비트 그룹마다 다른 모델 사용, 비(非)PASS 건은 다른 모델로 2차 판정.
2. **숫자 표기 정규화** — 대본 풀어쓰기(천구백사십이)와 STT 아라비아 표기(1942)를 같은 토큰으로 통일해 채점 아티팩트 제거.
3. **발화속도** — 휴지 포함 전체 길이 기준이라 저평가됨. 4.0음절/s 미만 건은 파형 분석으로 발화 구간만 재측정해 판정.
4. **장침묵 압축** — TTS 돌발 침묵(>0.9s)을 0.6s로 압축(`compress_silence.py`).
5. **의미 왜곡 의심 지점 패널 표결** — 자유 전사는 STT 언어모델 편향을 타므로, 음절 판별로 좁힌 프롬프트로 4개 모델 표결.

## 이슈 로그

① **beat14_en 장침묵** — 9.74s 중 약 5.5s가 문장 사이 침묵. 압축 후 4.24s, 재전사 완전 일치. 해결.

② **ko 비트6 "여든여덟" 오전사** — lite 계열 STT 2개가 "엿새 여덟"/"쉰여덟"로 받아씀. 동일 오디오를 상위 모델 2개가 완벽 전사(sim 1.0)해 오디오 정상으로 판정. 자막(88)이 이중 안전장치. 해결.

③ **ko 비트4 "도청에서" 모호** — 미해결(조건부). 서로 다른 TTS 렌더링 2개에서 자유 전사 4회 전부 "도청해서"(의미 반전). 음절 판별 표결은 2:2(전원 확신도 높음) = 해당 음절이 청각적으로 실제 모호. 자막이 "도청에서"라 시청자 오해 위험은 낮지만, 쿼터 리셋(매일 07:00 UTC) 후 재생성 권장:
```
GEMINI_TTS_MODEL=gemini-3.1-flash-tts-preview python3 scripts/shorts/generate.py docs/shorts/ep-p01-beats.json --lang ko --beats 4
python3 scripts/shorts/compress_silence.py docs/shorts/ep-p01_output/beat04_ko.wav
python3 scripts/shorts/qa_transcribe.py docs/shorts/ep-p01-beats.json --lang ko --beats 4 --model gemini-3.5-flash
```
후보를 2~3개 뽑아 음절 표결에서 3/4 이상 "도청에서"가 나오는 렌더링을 채택할 것.

④ **비트13 풀어쓰기 누락** — beats.json이 "55년"으로 문서 규칙(오십오 년) 위반 → 텍스트 정정. 오디오는 동일 발음이라 재생성 불필요.

⑤ **무료 티어 쿼터 실측** — TTS 프리뷰 모델은 분당 3회·일일 약 10회/모델. 대응: 4비트 묶음 합성 후 무음 분할(`chunked_tts.py`, 언어당 4호출), 429 시 서버 `retryDelay` 준수, 언어별로 모델 버킷 분리. 당일 한도 소진 시 리셋은 07:00 UTC(16:00 KST). 참고: `gemini-2.5-flash`는 신규 사용자에게 404(사용 불가) — 검수는 3.x 계열 사용.
