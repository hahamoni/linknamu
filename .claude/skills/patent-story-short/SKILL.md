# 특허 스토리 쇼츠 — 한 편 만들기

30~45초, 9:16, 비트 12~16개(비트당 2~3.5초). 아카이브 스틸이 주력, 생성 클립은 보조.
**같은 소재·같은 언어로 51.4만과 4.5만이 갈린 실측에서 나온 규칙이다. 대부분 수치가 붙어 있다.**

전신인 `faceless-mystery-short`(4컷×8초)와 다른 포맷이다. 그 스킬의 §4(숫자 TTS)·§5(한글 깨짐)는
여기서도 그대로 적용되고, 게이트가 같은 검사를 수행한다.

---

## 0. 순서

```
① 소재 잡기 → ② 사실 검증 → ③ 비트 대본 → ④ 게이트 → ⑤ 승인 → ⑥ 아카이브 수집 → ⑦ 생성·조립
                                              ↑
                              여기까지 크레딧 0. 반드시 여기서 다 잡는다.
```

**⑤ 승인 전에는 이미지·영상·음성을 절대 생성하지 않는다.** 편당 실측 약 22크레딧
(클립 8×2 + 그래픽 1.5 + 나레이션 0.15×28 — 2026-08 프리플라이트).
아카이브 스틸·커버·음악은 0크레딧이다.

## 1. 소재와 사실 검증

- 소재는 `docs/shorts/topic-bank-2026-08-26.md`의 특허 트랙에서. 수요 등급 강·중 우선.
- **"이 소재에서 유명하지만 사실이 아닌 디테일은 무엇인가"를 반드시 검색한다.**
  헤디 라머 편에서 "와이파이를 발명했다"가 검증에서 뒤집혔다 (Wi-Fi는 주파수 도약 미사용,
  특허청이 핵심 청구항을 선행기술로 거절). **뒤집힌 사실이 그 편의 내용이 된다.**
- 세우지 않은 통념은 반박하지 않는다. 과장을 되풀이하는 대신 문서가 실제로 말하는 것만 쓴다.
- 출처는 특허 원문(Google Patents)까지. 인용은 원문 그대로.

## 2. 프레이밍 법칙 — ★ 수요 검증에서 가장 크게 배운 것

**같은 이야기가 프레임에 따라 100~1000배 갈린다** (위저: 스토리 57.7만 vs '특허' 42뷰).

- **특허는 훅이 아니라 증거물이다.** 제목·커버·1비트에 "특허"를 간판으로 걸지 않는다.
  파는 것은 인물과 반전; 특허 문서는 중후반에 증거로 한 번 등장한다.
- 커버·제목은 인물/반전 중심: "이 특허의 발명자는 배우였다" (O) / "오늘의 특허 소개" (X)

## 3. 비트 구조 — 20편 실측의 핵심 (법칙 번호는 분석 문서와 동일)

| 법칙 | 규칙 | 근거 |
|---|---|---|
| 1 | **비트 2~3.5초, 총 12~16비트, 30~45초** | 승자 씬 중앙값 2.5s; 씬 4s↑는 같은 소재도 45K 천장. 60s 초과는 2.2K |
| 2 | **1비트 = 인물 얼굴** (아카이브 스틸). 문서·도면으로 시작 금지. 인물 비주얼 전체의 50%↑ | 승자 전원 인물 오픈; 도면 오픈 중 10만+ 없음 |
| 3 | **훅은 질문 또는 통념+반박 한 문장, 2초 안** | "How long did it take...?"(11M), "You might think X, but he didn't"(소형 채널에서도 작동). 죽는 훅: 카테고리 라벨·이름 소개·제목 낭독 |
| 4 | **문서는 정확히 1비트, 2~3초, 60~75% 지점** | 385K 편 66% 지점 2초; 문서가 주인공인 편은 전부 <1만 |
| 5 | **숫자·인용·아이러니 페이오프로 착지.** 구독 요청·채널 로고 금지. 댓글 유발 질문은 허용 | "한 달"+달력(11M), "$500"+묘비(634K); "구독·좋아요" 엔딩은 45K |
| 7 | **문장이 바뀌면 화면이 바뀐다** — 비트당 비주얼 1개, 나레이션과 1:1 | 무관 스톡 편 859뷰 |
| 9 | **불의·아이러니 아크를 찾는다** | 정보 나열의 천장은 56K; 불의 아크는 634K·385K |

비트당 나레이션: **한국어 6~21음절 / 영어 4~11단어, 한 문장.**
총량: 한국어 165~250음절, 영어 84~126단어.

## 4. 비주얼 소싱 — 3층

1. **아카이브 스틸 (주력, 50%↑, 0크레딧)** — 인물·시대 사진. Wikimedia Commons /
   Library of Congress에서 **퍼블릭 도메인 표시를 개별 확인**하고 출처 URL을 패키지에 기록.
   1930년 이전 미국 발행 사진은 PD. 편집 시 Ken Burns(느린 줌·팬)로 비트화.
2. **생성 클립 (보조, 2~3개)** — veo 8초 클립 1개를 **반으로 잘라 2비트**로 쓴다.
   프롬프트 문법은 전신 스킬 §6 그대로 (남색·청록, 단일 광원, film grain, no people,
   문서 컷엔 `no legible writing, no readable characters` 이중).
3. **문서/도면 (정확히 1비트)** — 특허 도면 실물 스캔(Google Patents PDF, PD).
   풀텍스트 페이지 금지 — 도면 부분 크롭만.

"no people" 규칙 개정: **생성 인물·본인 얼굴 금지는 유지. 역사 인물의 아카이브 사진은 필수.**

## 5. 오디오

- **음악 단일 트랙이 전체를 관통한다** (승자 전원). 소스는 **유튜브 오디오 라이브러리**
  (피아노/스트링/일렉트로닉, 30~60초) — Higgsfield는 단독 음악 생성 미지원(실측),
  무료 라이브러리가 라이선스도 안전하다. 클립 앰비언트는 음악 아래 낮게.
- 나레이션 숫자 처리·한글 깨짐 검수는 전신 스킬 §4·§5 그대로:
  - 쉼표 숫자 금지, 100 미만 고유어 단위는 한글로 ("여든여덟 개")
  - 자막(아라비아 숫자)과 나레이션 텍스트(풀어쓰기) 분리
  - 생성 직후 params.prompt 대조 / durationSec÷음절 4.5 미만 재생성 / 51.1535625초 폐기
  - 깨진 단어는 재생성이 아니라 **다른 말로 교체**

## 6. 게이트

```
python3 scripts/gate.py episode.json
```

episode.json: `{"title", "cover_ko", "cover_en", "beats": [{"ko","en","visual"}]}`
visual ∈ 인물 | 클립 | 문서 | 그래픽

자동 검사: 비트 수·비트당/총 길이, 1비트 인물+훅 문형, 문서 비트 수·위치·길이,
인물 비중 50%, 엔딩 금지어(구독·좋아요), 페이오프 존재, 숫자 오독 위험, 금지어.

**사람이 봐야 하는 것 (§7):**

- [ ] 커버가 약속한 것이 1비트에서 회수되는가
- [ ] 소개한 적 없는 것을 "그 X"로 부르지 않는가
- [ ] 통념을 뒤집는다면 통념을 먼저 말했는가
- [ ] 전체가 한 줄기인가 — 비트가 곁가지로 새지 않는가
- [ ] 불의/아이러니 아크가 있는가 (없으면 소재를 다시 본다)
- [ ] 비트마다 비주얼이 나레이션과 1:1인가 — 무관 스톡이 없는가
- [ ] 던져놓고 의미를 안 말한 숫자가 없는가
- [ ] 유명하지만 허구인 디테일을 걸렀는가 / 아카이브 사진의 PD 여부를 개별 확인했는가

**한 항목이라도 걸리면 대본을 고친다. 생성은 그 다음이다.**

## 7. 산출물 — 한 편 = 스토리 패키지

| | 내용 |
|---|---|
| 커버 헤드라인 | 한 10~16자 / 영 대문자 (인물·반전 중심, "특허" 간판 금지) |
| 비트 대본 | 12~16비트 × {한, 영, visual, 비주얼 설명} |
| 아카이브 스틸 목록 | 비트별 이미지 후보 + PD 근거 URL |
| 클립 프롬프트 | 2~3개 (언어 공용, 각각 2비트로 분할 사용) |
| 커버 프롬프트 | 한·영 각 1 |
| 나레이션 텍스트 | 숫자 풀어 쓴 버전 별도 |
| 음악 지시 | 무드·템포·길이 한 줄 |

**클립·스틸·음악은 언어 공용.** 한·영 2개 국어 비용 = 클립 2~3개 + 커버 2장 + 나레이션 + 음악.

## 9. 실전 개정 (2026-08-27, P01~P06 제작에서 실측)

### 9.1 구조 — 사용자 확정 원칙 3가지

게이트를 통과해도 아래 셋이 없으면 다시 쓴다. P01 v2가 "누군지도 모르겠고 반전도 없다"는
평가를 받고 전면 재작성된 근거다.

1. **도입 후킹** — 1비트에서 시청자를 붙잡는다 (질문형 또는 통념+반박). 게이트가 검사한다.
2. **마지막에 반전 또는 가장 중요한 정보** — 이름·정체·진짜 이유는 **13~14비트에 배치**한다.
   중반에 터뜨리면 남은 30초가 무너진다.
3. **쉬운 이야기** — 전문용어를 일상어로. "주파수 도약" → "채널을 계속 바꾸는 것",
   "두 장치를 맞물린 부품" → "악보로 박자를 맞췄다". 숫자는 던지지 말고 **즉시 의미를 붙인다**
   ("채널이 88개라, 따라잡을 수 없죠").

**착지는 하나만.** 정체 공개와 명대사 인용을 둘 다 끝에 놓으면 서로를 약화시킨다.
남는 쪽은 설명란·고정 댓글로 보낸다.

### 9.2 반전 배치 패턴 (P01~P06 실제 사용)

| 편 | 훅 | 마지막 반전 |
|---|---|---|
| P01 헤디 라마르 | "당신의 블루투스, 이 배우에게서 시작됐다면요?" | 정체 공개 — 할리우드의 전설 |
| P02 모노폴리 | "만든 건 우리가 아는 그 남자가 아니었죠" | 목적 반전 — 독점이 나쁘다고 가르치려던 게임 |
| P03 위저 | "특허엔 뭐라고 적혀 있을까요?" | 이름의 출처 — 그녀 목걸이 속 소설가 |
| P04 니콜스 큐브 | "먼저 나온 게 있었다면요?" | 단어 하나('여덟')가 판을 뒤집음 + 회한 인용 |
| P05 링컨 | "이 남자가 만든 발명품, 아무도 쓴 적이 없습니다" | 정체 공개 — 특허를 가진 유일한 대통령 |
| P06 휴지 | "앞으로 거세요 뒤로 거세요?" | 통설 자체를 뒤집음 — 발명자의 목표는 방향을 없애는 것 |

**정체 공개형에서는 1비트에 '알아보기 어려운 초상'을 쓴다.** P05는 1846년 수염 없는 링컨을
써서 마지막까지 정체를 숨겼다. 커버·초반에 유명한 얼굴을 쓰면 반전이 죽는다.

### 9.3 편집 (assemble.py) 실측 규칙

- **같은 사진을 연속 비트에 쓰지 않는다.** 불가피하면 두 비트를 **한 컷으로 병합**(`span`)해
  끊김 없는 롱테이크로 만든다. 시청자는 "같은 사진 반복"을 즉시 알아챈다.
- **자막은 중앙·52pt.** 하단 배치는 세로 화면에서 인물 얼굴과 겹치거나 잘린다.
  단, **서명·문서 카드가 화면 중앙에 오는 비트만 하단으로 내린다**(`bottom_beats`).
- 자막 번인은 **libass(.ass)** 로. drawtext 필터가 없는 ffmpeg 빌드가 흔하다.
- 편별 편집 스펙은 `ep-pNN-edit.json`으로 분리(`--edit`). 스크립트에 하드코딩하지 않는다.

### 9.4 나레이션 (TTS) 실측

- **빠른 템포를 명시 지시한다.** 기본 톤은 늘어진다. 실측: 지시 전 4.3음절/초 → 지시 후 5.5음절/초,
  같은 대본이 55.8초 → 42.5초.
- 의미가 뒤집히는 **최소대립쌍**('도청에서/도청해서')은 재샘플링으로 안 고쳐진다.
  **스타일 지시문에 발음을 유도**한다("명사+조사, [에] 음절을 명확히, 사이를 살짝 띄우기").
- 검수는 STT 대조 + **모델 교차**. lite 계열 STT는 '여든여덟'을 '쉰여덟'으로 듣는다 — 오전사를
  오디오 결함으로 오판하지 말 것. 상위 모델로 재검한 뒤 판정한다.

### 9.5 무료 티어 쿼터 실측 (Gemini, 2026-08 기준)

| 용도 | 상태 |
|---|---|
| TTS (2.5-flash / 2.5-pro / 3.1-flash) | **모델당 하루 약 10회.** 리셋 07:00 UTC |
| 이미지 생성 (전 모델) | **쿼터 0** — 첫 호출부터 429 |
| 비디오 생성 (veo 3.1 계열) | **쿼터 0** |
| 텍스트·STT | 넉넉함 (분당 제한만) |

→ **생성 이미지·영상은 무료 티어로 불가.** 대안 둘: ① Gemini 앱(Plus 구독)에서 수동 생성 후 첨부
② **코드 렌더링**(`render_diagram.py`, `render_card.py`) — 0크레딧이고 '정확히 88개' 같은
사실 정확성에서 생성 모델보다 우월하다.

### 9.6 비주얼 3층 갱신 — 코드 렌더링을 정식 층으로

1. 아카이브 스틸 (주력)
2. **코드 렌더링 — 다이어그램·인용 카드** (0크레딧, 결정적 재현)
   - `render_card.py`: 특허 원문 한 줄을 종이 스트립에 타자기체로, 핵심 단어 금색 강조.
     P04의 'eight', P06의 'certain direction'처럼 **반전의 근거를 문서 그대로 보여줄 때** 강력하다.
3. 생성 클립 (보조, 유료 계정일 때만)

### 9.7 아카이브 수집 실무

- Wikimedia는 **기본 User-Agent를 거부**한다. UA 헤더 필수. 429가 나면 지수 백오프로 재시도
  (일시적이며 대개 30~90초 후 풀린다). 다운로드 사이 4~12초 간격.
- 특허 도면은 Commons보다 **patentimages.storage.googleapis.com의 PDF**가 낫다
  (페이지 PNG는 썸네일인 경우가 있다). `pymupdf`로 200dpi 렌더 → 크롭.
- **PD 아닌 CC BY/CC BY-SA도 쓸 수 있다.** 설명란 크레딧만 지키면 된다. 라이선스는
  Commons API `extmetadata`로 개별 확인하고 패키지 문서 표에 남긴다.
- **도면 헤더에 발명자 이름이 인쇄돼 있다.** 정체 공개형에서는 초반 비트에 헤더가 보이지 않게
  크롭하고, 헤더 자체를 **마지막 반전 카드**로 쓴다 (P05 "ABRAHAM LINCOLN" 헤더).
